# 人工智能监管分类

## 何时读取

当任务涉及禁止类别、风险等级、高影响或高风险系统、通用模型、生成式AI、系统性风险模型、关键领域、附件或清单、技术门槛、重大决定、分类档案或重新分类时读取本文件。

本文件不预设每部AI法律都采用高、中、低风险分级，也不把任何法域的分类体系移植到另一法域。

## 基本原则

- 先识别法律分类的对象和机制，再分配义务。
- 分类必须来自该法的定义、正文、附件、实施文件和主管机关正式决定。
- 区分立法或行政机关制定类别的标准、企业可以直接适用的条件、官方清单或示例，以及企业的具体分类结论。
- 不得自行增加、拆分、合并或重新命名法定条件。
- 分类结论不足以单独证明合规；还需按角色、场景和时间连接适用义务。

## 第一步：识别分类对象

先确认法律实际分类的是哪一种对象：

- AI实践或被禁止的行为；
- AI系统、模型或产品；
- 产品安全部件；
- 特定用途、部署场景或法定领域；
- 对个人产生法律或重大影响的决定；
- 通用模型、生成式AI或具有系统性风险的模型；
- 训练计算量、能力、用户规模或其他技术门槛达到标准的模型；
- 特定角色实施的活动。

同一产品可能包含多个需要分别评估的系统、模型、功能或使用场景。不得只按产品名称作一次全局分类。

## 第二步：识别分类机制

根据法律原文判断属于哪一种或哪几种机制：

| 分类机制 | 判断重点 |
|---|---|
| 定义直接认定 | 是否完整满足法定定义及其限定语 |
| 领域或用途认定 | 系统是否在指定领域执行指定功能 |
| 产品监管路径 | 是否属于受监管产品或安全部件，并触发相应评定程序 |
| 附件或清单认定 | 是否逐项命中正式附件、清单和限定条件 |
| 一般风险标准 | 法律是否授权企业直接综合判断，还是仅供主管机关制定清单 |
| 重大决定标准 | 系统是否作出或实质影响具有法律或类似重大效果的决定 |
| 技术或能力门槛 | 计算量、能力、规模或其他量化门槛是否达到标准 |
| 主管机关确认 | 是否可以或必须申请确认、登记或获得决定 |

分类机制可能并行存在。例如，一部法律可以同时规定禁止行为、高风险用途、特定模型类别和一般透明度类别。

## 第三步：分开记录四个层次

分类分析必须分开记录：

1. **类别制定标准：**立法机关或主管机关决定新增、调整清单或类别时使用的因素；
2. **企业适用条件：**企业能够直接依据法律判断的定义、用途、门槛或法定领域；
3. **官方分类材料：**附件、清单、正式示例、指南、确认决定和技术文件；
4. **企业分类结论：**结合具体系统、用途、角色和证据作出的结论。

除非法律明确授权企业直接适用，一般的危害因素或清单制定标准不能代替正式清单、附件或法定定义。

## 禁止行为与其他分类的顺序

先检查禁止行为或不可接受的实践，再判断风险等级或特殊类别。命中禁止行为时，不得因为系统同时符合低风险、中风险或一般用途条件而继续按照普通分类上线。

禁止行为应单独记录行为、主体、对象、目的、手段、影响、例外和法律依据，避免只按技术名称判断。

## 清单和附件型分类

只有法律确实采用附件或主管机关正式清单时，才使用本节：

- 逐项核验对象、用途、部署场景、影响对象和限定条件；
- 完整保留项目中的连接词、排除语和行业范围；
- 不用清单标题或关键词匹配代替对完整条目的判断；
- 不将主管机关制定、调整清单的标准直接当作企业独立认定条件；
- 区分一般清单、强制评定清单、禁止清单及其他子清单；
- 清单修订后检查过渡期和存量系统重新分类要求；
- 官方示例和非官方业务示例分开标注。

## 排除、例外与降级条件

命中定义、领域或清单后，继续核验是否存在：

- 窄程序、准备性或辅助任务；
- 不实质影响决定结果的情形；
- 充分且独立的人类复核；
- 纯技术编辑、格式处理或质量改进；
- 研发、测试、个人或非商业使用排除；
- 国家安全、执法或其他特殊制度；
- 行业法已经覆盖并允许等效合规的情形；
- 明确规定的豁免、例外或降级程序。

不得凭风险较低的直觉自行降级。适用排除或例外时记录事实、法律依据、证明材料和重新评估条件。

## 角色与分类的结合

同一分类可能对提供者、开发者、部署者、进口商、分销商、使用者或其他角色规定不同义务。先按具体活动判断角色，再建立“分类结果—法定角色—适用义务”映射。

角色定义章节只说明基础角色。只有在某一分类下才触发的特殊义务，应归入相应分类的义务集合，避免把特殊要求误写成所有该角色的普遍义务。

## 分类结论记录

每个分类结论至少记录：

| 字段 | 内容 |
|---|---|
| 评估对象 | 系统、模型、功能、用途或场景 |
| 预期用途与实际部署 | 目标、用户、领域、输入输出和决定影响 |
| 公司角色 | 按该对象和场景判断的法定角色 |
| 分类机制 | 定义、领域、附件、清单、门槛或确认程序 |
| 命中依据 | 具体条款、附件、清单项目和事实 |
| 排除与例外 | 是否适用及证明材料 |
| 结论 | 禁止、高风险、高影响、其他类别、不适用或待确认 |
| 置信度与缺口 | 关键不确定事实和所需材料 |
| 确认程序 | 是否需要登记、通知或主管机关确认 |
| 义务集合 | 与角色结合后的适用义务 |
| 重新分类触发 | 功能、用途、数据、模型、角色、场景或法律变化 |

## 重新分类

检查法律规定及业务变化，至少关注：

- 功能、预期用途或部署场景重大变化；
- 模型、数据、自动化程度或决定影响发生变化；
- 提供方式、品牌、集成方式或公司角色变化；
- 出现严重事件或新的实际风险证据；
- 附件、清单、技术门槛或正式指南修订；
- 原分类依赖的排除条件不再满足。

重新分类时保留原结论、变化事实、新依据、生效时间和过渡措施。

## 自查表转化限制

- 可以把复杂定义转换为多个业务事实问题，但不得把一个法定标准错误改写成多个独立法律条件；
- 不得用内部打分或自创H1、H2等标签替代法律自身的分类结构；
- 一般标准、正式清单、排除条件和最终结论应分区呈现；
- 自动分类工具或问卷结果只能在法律允许的范围内作为辅助，不能代替必须进行的正式评定或主管机关决定；
- 信息不足或结论冲突时设置法务升级或主管机关确认路径。
