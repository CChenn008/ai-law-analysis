# 合规工作簿设计

## 何时读取

当交付物是Excel、多工作表合规清单、业务自查工具、结构化规则库或需要跨表导航的合规工作簿时读取本文件。

普通法律问答、单篇报告或不涉及表格结构的交付不读取本文件。实际创建或修改Excel时，同时遵循可用的电子表格技能和用户提供的模板。

## 设计目标

工作簿应让不同读者在同一套法律依据上完成不同任务：

- 业务人员能够查询规则和完成初步自查；
- 法务人员能够回查完整规则和依据；
- 管理人员能够了解使用路径和关键结论；
- 后续维护人员能够更新法律版本并追踪受影响内容。

不要为了“完整”把所有内容塞入一张表，也不要创建多个功能重复、相互矛盾的工作表。

## 资产模板使用

当用户需要完整的多工作表AI法律合规工作簿、没有提供优先级更高的模板，并且六表结构与任务复杂度相匹配时，可以使用 [../assets/AI法律合规工作簿模板.xlsx](../assets/AI法律合规工作簿模板.xlsx) 作为起始文件。

- 先复制资产模板并另存为本次交付文件，不得直接修改资产母版；
- 模板只提供工作表分工、表头、预留区域、配色和基础下拉，不提供任何特定法域的法律结论；
- 先识别目标法律自身的监管结构，再决定是否保留、重命名或停用03、04等模块；
- 目标法没有统一法定角色、风险等级或分类制度时，不得为了填满模板而自行创建；
- 先稳定02业务合规指引的大类和内容，再生成01目录及自查导航；
- 用户提供的模板、已确认结构或更简单的交付形式优先，不要求所有项目机械使用六张工作表。

## 先确定核心表，再设计其他表

先确定核心业务合规指引的读者、章节大类、表头和内容边界。目录、自查表和其他导航内容应当从稳定的核心大类派生。

大型工作簿按以下确认顺序推进：

1. 明确工作簿读者、用途和范围；
2. 确定各工作表功能及相互关系；
3. 确定核心业务总表的大类和表头；
4. 试做一个代表性章节；
5. 确认角色、禁止行为、分类、义务和示例的表达方式；
6. 批量生成核心表；
7. 生成目录和业务自查表；
8. 完成跨表及视觉检查。

用户已经确认某张表的结构后，不擅自刷新其他工作表或更改既定表头。确需联动修改时，先说明受影响范围。

## 常见工作表功能

根据项目需要选择，不要求固定数量或固定编号：

| 工作表类型 | 主要功能 |
|---|---|
| 使用说明与目录 | 介绍核心指引涵盖什么以及自查工具如何使用 |
| 业务合规指引 | 面向业务人员说明主要法律要求、边界和示例 |
| 适用范围与角色自查 | 初步判断受监管对象、地域适用和企业角色 |
| 监管分类自查 | 检查禁止行为、风险等级、特殊类别、清单和排除情形 |
| 法务规则底表 | 保存完整、原子化和可追溯的法律规则 |
| 法规与附件索引 | 保存文件状态、版本、官方来源和附件关系 |
| 业务改造矩阵 | 记录差距、责任团队、行动、期限和验收证据 |
| 更新台账 | 记录法律或工作簿版本变化及受影响结论 |

只有当读者、用途或维护方式确实不同，才拆分工作表。简单项目可以合并，复杂项目可以增加专项自查或行业模块。

## 使用说明与目录

- 主要说明核心业务合规指引呈现什么；
- 目录标题与核心总表的大类保持一致；
- 简要说明可以通过哪些自查表完成角色、适用范围或分类初筛；
- 不在使用说明中重复完整义务、复杂判断逻辑或法务底表字段；
- 核心总表大类尚未确定前，不先行固定目录。

## 核心业务合规指引

- 按业务问题或监管主题组织大类；
- 表头和字段要求参照 [output-templates.md](output-templates.md)；
- 同一大类的连续行在展示层可以合并大类单元格，避免逐行重复；
- 合并只用于展示，不破坏筛选、引用、数据结构或后续维护；
- 详细法律规则留在法务底表，业务表不堆叠无实际查阅价值的内部字段；
- 章节标题、编号和引用保持稳定，供目录和自查结果指向。

## 法务规则底表

- 作为法律追溯和维护基础，不直接替代业务指引；
- 使用稳定规则编号连接业务总表、自查表和改造矩阵；
- 完整保存主体、对象、条件、例外、期限、证据、后果和来源；
- 强制、鼓励、自愿和内部增强措施分开；
- 与普通企业无关的特殊主体规则可以保留并标记不适用，不必进入核心业务表。

## 业务自查表

业务自查表的问题必须由业务人员依据事实回答。根据复杂度，可以拆分为角色与适用范围自查、监管分类自查或其他专项自查。

- 每题指向一个明确的事实、清单项目或法律条件；
- 复杂定义可以拆成事实问题，但不得改变法定条件的组合关系；
- 提供“是／否／不确定”或其他适当选项；
- 允许填写补充事实和证据；
- 结果提示应指向业务总表章节、后续义务或法务复核；
- 禁止行为、高风险或其他特殊类别、重大修改和结论冲突设置升级条件；
- 不用内部评分替代法律规定的正式分类机制；
- 自查表只作初筛，不伪装成自动法律结论。

## 跨表关系

至少建立以下关系：

- 目录大类对应核心业务总表大类；
- 自查问题对应法律条件、清单项目或稳定规则编号；
- 自查结论对应核心总表章节或适用义务集合；
- 业务总表内容能够回查法务底表和法律依据；
- 业务改造动作能够回查适用规则；
- 法规索引能够说明法律依据的版本和状态。

不要求所有关系都通过公式实现。可以使用稳定编号、超链接、命名区域或清晰的文字指引，选择最易维护的方式。

## 公式与可编辑区域

- 用户输入、下拉选项和自动结果使用不同的视觉样式；
- 结果由输入决定时优先使用可审计公式，不硬编码重复结果；
- 公式引用其他工作表时使用明确、稳定的区域；
- 不使用难以维护的整列引用或无说明的复杂公式；
- 留出“不确定”和法务复核路径，避免公式强制给出无条件结论；
- 修改表格结构后检查公式、数据验证、条件格式和引用范围是否同步。

## 视觉和可用性

- 大类、表头、正文、输入区和结果区形成清晰层级；
- 长文本合理换行并设置足够行高，不截断关键条件；
- 冻结标题行或关键列，便于浏览大型表格；
- 仅在有助于理解时合并单元格，计算区域避免合并；
- 颜色用于表达输入、提示、风险或状态，不只作装饰；
- 工作表名称简洁、稳定并与使用说明一致；
- 避免无内容的空白工作表和过度格式化的无用区域。

## 版本与修改控制

- 修改现有工作簿时，以用户最近修改的文件为基础；
- 保留用户已有内容和修改，除非用户明确要求删除；
- 不直接覆盖成品文件，按照当前项目或用户指定的命名规则另存；
- 用户调整某个章节、表头或逻辑时，只修改授权范围；
- 跨表联动确有必要时，说明具体受影响的工作表和字段；
- 文件名和版本号遵循当前项目规则，不在通用技能中固化某一日期格式。

## 完成前检查

- 每张工作表的读者和功能是否明确且不重复；
- 目录与核心总表大类是否一致；
- 法务底表、业务指引和业务自查表是否保持用途分离；
- 自查问题、结果和核心章节是否能够对应；
- 同一大类是否避免逐行机械重复；
- 法律依据、规则编号和跨表引用是否有效；
- 公式、数据验证和条件格式是否正常；
- 是否存在文本截断、错位合并、不可读颜色或异常空白；
- 最终文件是否基于最新版本并按用户要求另存。
