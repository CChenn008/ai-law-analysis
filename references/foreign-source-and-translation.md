# 外文来源获取与全量翻译

## 何时读取

输入为非中文法律文件、外文法律网页、网页中的文件下载链接、扫描版外文文件，或者任务需要外文全文翻译时读取本文件，并同时读取 [source-and-status-control.md](source-and-status-control.md)。

本文件规定来源取得、文件真实性、文本提取、全量翻译、覆盖核验和失败披露。它不改变目标法律的实体规则，也不授权绕过登录、验证码、付费墙、访问控制或其他技术限制。

## 先确定任务范围

根据用户请求区分：

1. **完整法律分析：**取得官方原文后，先形成并单独交付全量中文译文，再开展法律状态、监管结构、适用范围、角色、分类、义务和处罚分析；
2. **全文翻译：**交付完整译文，不自动扩展为完整法律意见；
3. **局部条款或专题问题：**可以只翻译支持该问题所需的范围，但仍保留原文位置、版本和法律状态控制；
4. **文件定性、效力或版本核验：**翻译足以支持判断的内容，不因文件为外文而自动扩大任务；
5. **用户提供中文译文：**确认其来源和覆盖范围，并用官方原文核验关键定义、义务、例外、日期、金额、处罚和附件。未经核验的译文不得替代官方控制文本。

## 识别链接和文件

先判断用户提供的是：

- 直接文件下载链接；
- 官方文件详情页或公报目录页；
- 正文直接发布在网页中的法律页面；
- 经跳转、查询参数或临时令牌生成的下载链接；
- 登录页、验证码页、访问拒绝页或下载失败页；
- PDF、Word、电子表格、压缩包、图片或其他格式；
- 扩展名、响应类型和实际文件内容不一致的对象；
- 包含正文、附件、修订文本或多个语言版本的压缩包。

有工具和权限时，可以沿官方详情页取得实际文件并保存原始副本。遇到压缩包时，先查看文件清单和类型，再提取与任务相关的文件；不得执行其中的程序或未知脚本。

不得仅凭网页标题、搜索摘要、链接文字、文件名或HTTP成功状态认定已经取得法律全文。应检查实际内容是否为目标文件，是否包含正文和应有附件。

## 建立来源与文件台账

对每个控制文件记录：

| 字段 | 核验内容 |
|---|---|
| 文件标识 | 多文件任务中的唯一编号 |
| 正式名称及编号 | 原文名称、中文译名、编号和文件类型 |
| 发布机构与法域 | 立法机关、政府、监管机构及适用法域 |
| 官方详情页 | 能说明文件身份和状态的官方页面 |
| 实际文件地址 | 本次取得文件的下载地址或正文地址 |
| 查询和下载日期 | 实际访问及保存日期 |
| 文件格式 | HTML、PDF、DOCX、XLSX、ZIP、图片或其他格式 |
| 文件大小 | 用于识别空文件、错误页或异常下载 |
| 文件摘要 | 工具可用时记录SHA-256，固定本次分析使用的副本 |
| 语言和控制版本 | 官方语言、多语言版本及控制文本 |
| 关键日期和状态 | 通过、公布、生效、适用日期及法律状态 |
| 完整性 | 正文、序言、定义、附件、附表、表格、脚注及修订标记 |
| 取得限制 | 登录、访问限制、损坏、缺页、OCR或版本不确定性 |

临时链接可能失效，除实际文件地址外还应保留稳定的官方详情页。文件名、扩展名或下载地址不能单独证明文件身份，应结合文件正文、发布机构信息、编号、日期和官方页面核验。

## 保存控制文本和工作副本

将材料分层保存：

1. **原始控制版本：**实际取得的官方语言文件和附件，不修改内容；
2. **可检索工作副本：**从网页、PDF、Word或OCR结果提取的结构化文本，保留页码、条款或其他原文定位；
3. **全量中文译文：**与原文结构对应的分析辅助版本；
4. **分析成果：**法律解读、规则底表、业务指引、自查表或改造清单。

原始文件和工作副本不得相互覆盖。网页正文应保存稳定链接、查询日期和必要的页面定位；文件下载链接与详情页应分别记录。

## 提取文本和OCR

- PDF任务使用可用的PDF工具；扫描件和图片先OCR；
- 完整保留标题、序言、正文、定义、例外、过渡条款、附件、附表、表格、脚注、页眉页脚中的实质内容和修订标记；
- 去除重复页眉页脚或版式噪声前，确认其不包含文件编号、版本、日期或限制条件；
- OCR后抽样核对条款编号、否定词、连接词、金额、比例、日期、专有名词、表格和附件标题；
- 页面缺失、文本层为空、字符错乱、表格结构丢失或OCR质量不足时，不得直接进入完整翻译和分析；
- 多文件或多语言包应先确认正文、附件、实施文件及各语言版本之间的关系。

## 全量中文翻译

完整分析非中文法律时，全量中文译文是分析前置成果，并应与法律分析分开交付。翻译必须：

- 保留文件标题、编号、发布机构和原文结构；
- 保留条、款、项、目编号及其层级关系；
- 完整翻译序言、正文、定义、例外、过渡条款、附件、附表、清单、表格、脚注和修订标记；
- 准确保留“且”“或”“除非”“不得”“仅在”等连接词、限定词和否定词；
- 保留日期、期限、金额、比例、技术门槛、单位和公式；
- 统一术语；法定术语首次出现或存在歧义时保留原文；
- 保留交叉引用并能够回查对应原文位置；
- 只翻译，不概括、不删减、不改写成业务建议，不把解释或法律意见写入译文。

存在多个同等正式语言版本时，记录本次翻译依据的版本；版本之间存在实质差异时，列为待核验事项，不自行消除冲突。

## 长文件分批与覆盖台账

长文件可以分批翻译，但在开始分析前必须合并并核对连续性。覆盖台账至少记录：

| 字段 | 内容 |
|---|---|
| 文件标识 | 对应来源台账中的控制文件 |
| 原文范围 | 页码、章节、条款、附件或表格 |
| 内容类型 | 正文、定义、附件、附表、表格、脚注等 |
| 翻译状态 | 未开始、进行中、已完成、待复核或无法处理 |
| 中文位置 | 对应译文文件、章节或条款 |
| 疑难术语 | 保留的原文、歧义和处理方式 |
| 缺失或异常 | 缺页、乱码、OCR错误、结构丢失等 |
| 复核结果 | 连续、完整、存在问题或等待材料 |
| 复核证据 | 页数、条款数量、附件数量或交叉引用检查 |

合并后检查：条款编号是否连续，正文与目录是否对应，附件和表格是否齐全，脚注和交叉引用是否可回查，是否存在重复翻译或批次之间的遗漏。

## 失败、限制与停止条件

下列情况不得表述为已经取得、翻译或核验全文：

- 链接只返回登录页、验证码页、访问拒绝页、错误页或空文件；
- 下载对象与页面描述、文件名或预期格式不一致；
- 文件损坏、缺页、版本不明或无法确认发布机构；
- 正文、定义、附件、表格、脚注或修订标记缺失；
- OCR质量不足以可靠识别关键条件；
- 只有新闻稿、摘要、二手介绍或未经核验的非官方译文；
- 分批翻译后无法证明条款和附件覆盖完整；
- 多语言官方版本存在冲突且无法确定控制文本。

可以检查用户提供的链接、对应官方详情页和可验证的官方替代发布位置，但不得绕过访问控制。仍无法取得材料时，停止受影响的完整翻译或分析环节，并记录：已经读取的材料、缺失内容、尝试过的官方路径、当前仅能支持的有限结论、需要用户补充的文件，以及补充材料后应重新执行的步骤。

## 交付分层

完整外文法律分析至少应将以下成果分开：

1. 来源与文件台账；
2. 原始控制文件或其稳定官方链接及保存位置；
3. 可检索外文工作副本或OCR结果；
4. 全量中文译文；
5. 翻译覆盖台账；
6. 独立法律分析成果。

在最终交付中，至少单独提供全量中文译文和法律分析，并说明实际读取的控制文件、版本及截至日期。工作副本和覆盖台账可以根据用户交付形式作为独立文件、附录或审计记录，但不得省略其核验功能。

## 完成标准

完成外文来源和翻译流程后，应能够回答：

1. 实际打开并保存了哪些官方页面和文件；
2. 哪份原文是控制版本，如何固定本次使用的副本；
3. 正文、定义、附件、表格、脚注和修订标记是否完整；
4. OCR或文本提取存在哪些限制；
5. 中文译文覆盖了哪些原文范围，是否存在未解决问题；
6. 译文和法律分析是否严格分离；
7. 哪些结论仍受来源、版本、语言或完整性缺口限制。
